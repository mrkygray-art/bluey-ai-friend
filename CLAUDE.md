# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Bluey is an AI companion for people who don't think of themselves as AI users: a friendly blue orb in a small digital world who helps people get better results from AI without teaching them prompt engineering ("teach without teaching"). Plain HTML/CSS/JS front end (no build step, no framework), Vercel serverless functions in `api/`, OpenAI API. Live at bluey-ai-friend.vercel.app; Vercel team `power-quote`, project `bluey-ai-friend`, deploys on push to `main`.

Development moved from ChatGPT to Claude Code on 2026-10-06. Earlier history (alpha numbers, "Add files via upload" commits, `codex/*` branches) came from ChatGPT/Codex and GitHub web uploads.

## Commands

- `npm install`, then `vercel dev` — serves the static app and the `/api` functions locally. Needs a local `.env` with `OPENAI_API_KEY` (copy `.env.example`; `.env` is git-ignored).
- There is no build, lint, or unit-test setup. The Brain Lab (below) is the test suite.

## Architecture

**Front end is a stack of patch layers.** `index.html` (~2,400 lines, holds the original app inline) loads `alpha7.css`…`alpha40.css` and `alpha7.js`…`alpha40.js` in order. `alpha40.js` then injects `alpha41.js`…`alpha46.js` (and `alpha13.js` also injects `alpha43.js`); `alpha46.js` / `index.html` pull in `alpha47-quiet-stage.js` and `alpha47-mobile-polish.css`. Each later layer overrides or monkey-patches earlier ones, so **a behavior can be defined in several files and the last loaded wins**. Before changing a behavior, grep every layer for it. Consolidating these layers is planned, one area at a time with testing, never a big-bang rewrite.

**API (`api/`, each file is a Vercel function; `_`-prefixed files are helpers, not routes):**
- `chat.js` — the brain. Big system prompt (character + "Bluey Intelligence" rules), OpenAI Responses API with a strict JSON schema returning `{reply, behavior, spellingSuggestion, brain}`. `brain` holds `mode` (DO/DISCOVER/GROW), goal/goalThread, `contextShifted`, readiness, promptQuality, `initiativeLevel` 0–4, opportunity rung/idea distance, environment, etc. The brain record is developer telemetry and must never be shown to users. Up to 5 images (data URLs, png/jpeg/webp/gif). Model from `BLUEY_MODEL`.
- `transcribe.js` (speech-to-text, 15 MB), `speech.js` (TTS, ≤4,096 chars), `document.js` (PDF/Word/Excel via pdfkit/docx/xlsx), `prompt-workshop.js`.
- `_limit.js` — best-effort in-memory per-IP hourly limit + daily cap, applied to all five endpoints. Resets per instance; the real backstop is the OpenAI account's monthly spend limit.

**Steer buttons** — `steer.js` + `steer.css` (loaded after `alpha40.js`). `chat.js` returns `brain.isDraft`; `steer.js` wraps `window.fetch` to read each `/api/chat` response (parsed before the caller gets it) and wraps `add()` to show Shorter / Warmer / More specific / Different angle under the latest draft only; a tap calls `send("Make it shorter.")` etc. Server side, `chat.js` detects a revision turn (latest user message starts with "make it/this/that", "shorter", "warmer", "try a different angle"…, right after an assistant message) and swaps the random reply-style nudge for an "edit your previous draft, keep every detail" nudge — the random nudges ("choose a fresh answer shape") made revisions start over and drop facts. Replies are capped at 4,000 output tokens; a cut-off reply returns a friendly 502. `steer.js` also adds a **More ▾** dropdown (formal, casual, simpler, bullets, plus two that prefill the composer) and, when `brain.assumption` is set, a "💭 … If that’s not right, just tell me." line (the old **Fix that** button was removed: unclear on its own). The revise-turn regex also matches "use simpler", "turn it into", "change it", "actually".

**Preferences** — `preferences.js` + `.css`. `brain.preferenceNoticed` → "Remember this for next time?" card; saved list (max 8, localStorage `bluey-preferences`) is added to every `/api/chat` body as `preferences`; `chat.js` sanitizes (strings, ≤120 chars, ≤8) and appends them to the instructions as style preferences only. **Remembered ▾** in the session tools lists/forgets them (full-width card on phones). Bluey must never claim cross-device memory.

**Greetings** — `greetings.js` redefines `blueyFirstMeet` / `blueyReturningMeet` (index.html calls them 420 ms after load): ~30 returning lines, weekday lines, July 4th Digital Day lines, no repeat of the last 8 (localStorage `bluey-greeting-recent`). Time-of-day lines stay in the status line (`blueyTimeRitual`). The original first-meeting intro never showed (it searched for the default greeting text after it had changed); `greetings.js` sets it directly.

**Greeting placement** — `follow-copy.css` + `follow-copy.js` (all screen sizes) make `.stage-copy` (greeting + status) a fit-to-text column that follows the orb's live position every animation frame, as Bluey drifts left/right and forward/back (the orb's size changes); it flips above him if there's no room below and stays on screen near edges. Selectors start with `body .app .stage` to beat the older phone stack in an `index.html` `@media(max-width:700px)` block (which used `!important` top/left/right) and `alpha47-mobile-polish.css` (injected late by `alpha46.js`).

**Light bulb / tap-to-answer card** — `tips.js` + `tips.css`. `chat.js` returns `brain.betterPrompt`, `brain.betterPromptWhy`, and `brain.tipSlots` (one `{blank,label,options[≤3]}` per `[blank]`; empty options = text box for personal details). Server: drops a 💡 with >2 blanks, strips an unstated "first-time", normalizes slot brackets, dedupes, and adds a slot for any blank the model forgot. `tips.js` builds a card: the sentence (added words `<mark>`ed, blanks as `.bluey-fill` that fill live), chips + "Other…" per slot, and **Write it** (disabled until every blank is filled; sends the filled sentence). If the brain is asking (`!isDraft` and `needsQuestion`/`DISCOVER`) the card opens inline under Bluey's reply with no 💡; otherwise a 💡 under the user's message opens it. After the card is answered, `chat.js` detects that the user is replying to Bluey's own short question (previous assistant message <400 chars with `?`/"tell me"/"let me know") and swaps the reply-style nudge for "deliver the full result now, don't ask again, state assumptions" (live bug: 2 of 3 filled cards got a second question). Brain Lab case `answered-delivers`. The scorer counts "tell me / let me know / share / paste / send me / upload" as asking (no `?` needed). Hides `#bluey-prompt-start`. **The real test is `scripts/tip-eval.mjs`** (local only, `.vercelignore`d; reads `.env`): A/B per vague request with hidden background; blanks answered the way a person uses the card (pick the fitting chip or type ≤10 words); blind judge scores, invented facts (with a quote), and `tipFocus` 1–5. Pass bar: ≥80% wins, ≥ +1.5 avg, 0 invented, focus ≥ 4, no 💡 on clear requests. Averages can hide one bad 💡, so add targeted Brain Lab cases for known failures (`tip-proposal`, `tip-asking`). Restart `vercel dev` between runs (the per-IP limiter counts test calls). Brain Lab also checks every blank has exactly one slot, ≤3 distinct chips, short labels.

**Hand-off kit** — `chat.js` returns top-level `handoff` (`title, platform ∈ Claude|ChatGPT|Gemini|NotebookLM, feature (enum, server keeps it only if it belongs to that platform), why, alsoPlatform, alsoFeature, alsoWhy, prompt`) for jobs Bluey can't do here (build/run apps, images/video, schedules, accounts, long research, document workspaces). Rules under "HAND-OFF KIT"; a per-turn `handoffIntent` nudge (build/create … app/website/dashboard/tool/logo/video, or every Monday/daily/remind me) forces the hand-off and forbids implying Bluey will do it (live bug before: "what time should I send it?"). `handoff.js` + `.css`: card with Copy prompt, Open (copies; `?q=` prefill for ChatGPT/Claude under 1,800 chars; Claude Code → claude.ai/code, Codex → chatgpt.com/codex), Download PDF via `api/document.js` **direct content mode** (`content:{title,paragraphs,bullets}` → no model call, exact text). Test: `scripts/handoff-eval.mjs` (original vs filled super prompt through a stand-in OpenAI assistant, blind judge, platform fit 1–5; can't run Claude Code/Gemini itself, so it measures the prompt). Brain Lab: `handoff-build`, `handoff-schedule`, `handoff-image`, `handoff-none`; runner passes `_handoff`. **Official help sites** (`OFFICIAL_DOCS` in `chat.js`; listed in the prompt under "OFFICIAL HELP SITES"): on a `handoffIntent` turn the `web_search` tool gets `filters.allowed_domains: OFFICIAL_DOCS`, and `handoff.steps` (3–7 beginner steps from those pages) plus `sources` (official pages, or citations as a fallback) show in the card as "How to set it up" and "Official help" (help-center home if no search). Super prompts must ask for the finished result (not a plan), list assumptions, and self-check that the 1–3 key details are present as values or [blanks]. Studying several of your own documents → NotebookLM hand-off. `sources.js` skips its list when a hand-off card is shown. Eval history (4 runs, pass on run 4: 8/8, +3.0, fit 4.5) is in the README.

**Web search** — `chat.js` offers OpenAI's `web_search` tool (with `include: ["web_search_call.action.sources"]`) only while `searchAllowed(req)` (`_limit.js`: 15 searches per visitor per day, 300 per day overall, counted with `noteSearch` only when the model actually searched); otherwise the instructions say search is unavailable. Rules are under "WEB SEARCH" (search for current/specific facts, never for writing or general knowledge, never claim a search that didn't happen). The response gets top-level `sources` (title + url) and `searched`; the server keeps only sources whose cleaned URL (utm stripped, no trailing slash) appears in the search results or citations, and strips markdown links from `reply` (bold is kept now; see Formatted replies). `sources.js` + `.css` show a Sources list under the reply and swap "Thinking…" for "Still working on it…" after 8 s (searches take 20–40 s). A per-turn `findIntent` nudge (find / look for / openings / hiring / others like this) makes the reply lead with specific results and a stated guess (the rules alone produced a first pass only 1 in 3 times). Test: `scripts/search-eval.mjs` (collect without/with, blind judge with its own web search, opens every source link and retries failures in real Chrome, because some sites answer scripts with 405 but load fine). Brain Lab cases `search-jobs`, `no-search-writing`; the runner passes `_searched`/`_sources` into `checkExpectation`.

**Things to do together (offers) and greeting promises** — `chat.js` returns top-level `offers` (≤3 strings in the user's voice, ≤60 chars after cleaning; forced empty on drafts and hand-offs). Prompt sections "ROUND AND BLUE", "BLUEY'S TIPS", and "CONVERSATION STARTERS AND GREETING PROMISES" (offer 2–3 things on hello / bored / surprise me / greeting called in; never "I don't have a saved thought"; no offers on drafts, tasks, questions they must answer in words like their city, or sad moments; don't quote the offer wording in the reply). `STARTERS` (28) + `startersNote()` suggest 4 random ones per turn for variety. `greetings.js` wraps fetch and adds `greeting` (the text in `.stage-copy>.greeting`, ≤200 chars) to every `/api/chat` body; `chat.js` adds it to the turn's instructions as ON-SCREEN GREETING. The old "I had a thought and saved it just for you" line now reads "I had a thought just for you. Ask me what it is!" `offers.js` + `.css` (after `sources.js`) read the response like `sources.js`, show the offers as pills with a tiny blue ball under the reply, `send()` the text on tap, and clear all offer rows when any user message is added. Source text for the adventures: `docs/bluey-stories.txt`.

**Storybook life (lore)** — `api/_lore.js`: chapters (round-and-blue family and the eight adventures with the neighbors ChatGPT/Claude/Gemini, each with Bluey's Tip; Digital Day July 4th, the name/K.Y., life timeline, Great Printer Incident, friends, hobbies, "what are you doing" teaching scenes, philosophies, rooms, quirks, interview, date, meeting someone, secrets). `pickLore(lastUserText)` adds up to 3 matching chapters plus an index of all titles, only when the message is about Bluey ("you/your/Bluey", playful asks like "tell me a secret", or Bluey-world names like Fib, Pixel One, the Great Printer Incident) and isn't a task (`TASKY`, "for my/our"). Common words (echo, ping, captcha, fib) count only after "who is / tell me about". Birthday moved from July 7 to **July 4th** (Digital Day) in `chat.js`, `greetings.js`, and `index.html` (`BLUEY_BIRTHDAY`); old `alpha9.js` birthday lines still say July 7 but are unreachable (brain-first). `chat.js` keeps a short origin story under "HOW BLUEY GOT HIS NAME" with `originAsk` random starting points. Brain Lab: `origin-*`, `lore-birthday`, `lore-doing`, `lore-fib`, `lore-not-in-task`. When a searched reply has sources, the server also strips bare URLs from the reply text.

**Bottom controls** — `controls.js` + `.css`: a round blue **+** (`.bluey-plus`, prepended inside `#form`, left of the textarea) opens one menu: **Add photos & files** (`#bluey-file-input`, multiple, images + pdf/docx/doc/txt/md/csv), **Take a photo** only when `(pointer: coarse)` (`#bluey-camera-input`, `capture="environment"`), the Sound switches, and a slot `.bluey-plus-remembered` that `preferences.js` renders **Remembered ▾** into (`window.blueyRenderRemembered`). New controls go in this menu. `#bluey-voice` / `#bluey-sounds` are moved (not copied) into it, so all code that finds them by id still works; a MutationObserver puts a 🔇 badge on the + when Voice is off. `#bluey-attach` (old Add photos) and `#bluey-files` are hidden in CSS; `#bluey-photo-input` is unused. Composer buttons are styled by `.composer button` in older CSS, so menu selectors start with `.composer`. Click-outside handlers ignore detached targets (`e.target.isConnected`), because Forget re-renders the list. "New chat" no longer has a ＋ (alpha36). "Save chat" (alpha36's export button, found by its aria-label) is hidden in CSS; its code stays. `controls.js` also replaces `blueyShowSuggestion` (alpha7) with a no-op, so the "Small spelling suggestion" card no longer shows; the composer keeps `spellcheck="true"` for native squiggles + right-click fixes. `chat.js` still returns `spellingSuggestion` (unused).

**Files** — `files.js` + `.css` (loaded after `controls.js`). `blueyAddFiles(list)`: images join `blueyPhotos` (max 5, via alpha7's `blueyReadPhoto`); PDF via pdf.js 4.10.38 (`import()` from cdnjs, `isEvalSupported:false`, cross-origin worker handled by pdf.js), .docx via mammoth 1.13.0 (script tag with SRI), txt/md/csv as text — all in the browser, only text is sent. A PDF with <30 non-space characters is a scan: its first pages are rendered to JPEG and added as photos. `.doc` gets Save-As advice; other types a plain refusal. Docs `{name,kind,pages,text,sent}` (max 5, **250,000 characters total**, never truncated, refused with a message) live in `sessionStorage` `bluey-documents`; a tray above the composer shows chips (pages · words, CSV rows) with ×; after the first successful send a chip row is added under that user message and the tray says "In this chat". `window.fetch` is wrapped: every `/api/chat` and `/api/document` JSON body gets `documents` while any are attached (so follow-ups keep them); the client checks `documentsReceived`. Long text pastes (≥4,000 chars) become a "Pasted text" doc; non-image file pastes and drag-and-drop go through `blueyAddFiles`. `brain-first.js`: with a newly added (unsent) doc, the message always goes to the brain, and an empty Send becomes "Please take a look at this." New chat calls `blueyClearDocuments`. Server: `chat.js` sanitizes `documents` (≤5, same 250k cap → 413), inserts one user input item **right before the latest user message** (`documentBlock`: name, kind, pages, words, `<<<DOCUMENT n START>>>…END>>>`), raises `max_output_tokens` to 8000 when docs are attached, and returns `documentsReceived`. Rules are under "DOCUMENTS AND LONG PASTES" (complete text; never claim it's cut off unless it stops mid-sentence; cite parts; no question → short summary + ask; a file that isn't attached → ask them to add it with +). `document.js` gets the same docs. Test files for the Brain Lab are `DOC_RESUME` / `DOC_SALES` in `brain-eval.js`.

**Formatted replies** — `format.js` + `.css` (loaded **before** alpha7.js). `blueyFormat(text)` builds `div.msg.assistant.bluey-formatted` from DOM nodes (never innerHTML) with `data-raw`: ### headings, - / • / 1. lists (one nested level), **bold**, *italic*, `code`, fenced code, pipe tables, ---. `index.html` `add()` and alpha36's restore use it for assistant messages; alpha36 saves `dataset.raw`, so a refresh re-renders. `blueyPlain` strips Markdown for speech (`speak` is wrapped on DOMContentLoaded) and Copy; `blueyCopyReply` writes text/html + text/plain. Server: the "FORMATTING:" section near the end of the prompt (lists on their own lines with "- ", headings for long answers; drafts to send stay plain); `chat.js` no longer strips `**bold**` (it still strips markdown links). With the rule only at the top of the prompt, a packing list came back as bare lines.

**Add to home screen (PWA)** — `manifest.webmanifest` + `icons/` (rendered by `scripts/make-icons.cjs` from the orb's CSS: transparent 192/512 + favicons, maskable 512 and apple-touch 180 on white; `icons/icon.svg` is a hand-made SVG of the same ball) + `sw.js` + `pwa.js` (loaded after `files.js`). `sw.js`: never touches `/api/` or other origins; same-origin GETs are network-first (8 s for pages, 15 s for files) with a runtime copy, so it opens offline; `/index.html` is keyed as `/`, other pages by their own path (so `/brain-lab.html` can't replace the home page), redirected responses aren't stored. **Brain first** — `brain-first.js` (loaded last; re-installs itself every 300 ms because alpha40 loads alpha41–47 later and they re-wrap `send`). ## Rules

- **Numbers must come from the code.** Count test cases from `brain-eval.js` / `brain-lab.html`, never from UI labels or commit messages. Example: the beta lab's label says "39 tests" but only 19 cases exist in any branch; the 20 "real-human" scenarios were never committed. Public text (README, portfolio) currently says 39 by the user's choice; don't repeat it in new text, and don't "fix" it unasked.
- **Every brain change ships with Brain Lab cases committed to the repo**, so published claims can be checked.
- **Cost:** never expose a way for visitors to trigger many paid calls (keep the Brain Lab blocked on deployments, keep `_limit.js` on every OpenAI endpoint). Running the lab locally costs a few cents per run; say so before running it.
- **Honesty is a product feature:** Bluey must never claim a memory, file, image, account, or capability that doesn't exist. Keep the "not in this alpha" statements in `chat.js` true.
- **Tone:** UI copy is plain, warm, short, for first-time and hesitant AI users. No jargon, no lectures about prompting.
- **README is public** (github.com/mrkygray-art/bluey-ai-friend) and read by recruiters. Update it in the same commit as any visible change, and keep every claim true to the code. The same project is described in the portfolio (`~/projects/ky-gray-portfolio`: `#bluey` in `index.html`, `[proj-bluey]` in `api/_askky-knowledge.js`) and the GitHub profile README (repo `mrkygray-art/mrkygray-art`); tell the user when those may need updating, don't edit them unasked.
- **One source of truth:** changes go through this local repo. If GitHub has commits you don't (web uploads), `git pull` before editing.
