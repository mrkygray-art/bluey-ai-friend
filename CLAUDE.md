# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Bluey is an AI companion for people who don't think of themselves as AI users: a friendly blue orb in a small digital world who helps people get better results from AI without teaching them prompt engineering ("teach without teaching"). Plain HTML/CSS/JS front end (no build step, no framework), Vercel serverless functions in `api/`, OpenAI API. Live at bluey-ai-friend.vercel.app; Vercel team `power-quote`, project `bluey-ai-friend`, deploys on push to `main`.

Development moved from ChatGPT to Claude Code on 2026-10-06. Earlier history (alpha numbers, "Add files via upload" commits, `codex/*` branches) came from ChatGPT/Codex and GitHub web uploads.

## Commands

- `npm install`, then `vercel dev` — serves the static app and the `/api` functions locally. Needs a local `.env` with `OPENAI_API_KEY` (copy `.env.example`; `.env` is git-ignored).
- There is no build, lint, or unit-test setup. The Brain Lab (below) is the test suite.

## Architecture

**Front end is a stack of patch layers.** `index.html` (~2,400 lines, holds the original app inline) loads `base.css` (the old `alpha7.css`…`alpha40.css`, merged in order) and `alpha7.js`…`alpha40.js` in order. `alpha40.js` then injects `alpha41.js`…`alpha46.js` (and `alpha13.js` also injects `alpha43.js`); `alpha46.js` / `index.html` pull in `alpha47-quiet-stage.js` and `alpha47-mobile-polish.css`. Each later layer overrides or monkey-patches earlier ones, so **a behavior can be defined in several files and the last loaded wins**. Before changing a behavior, grep every layer for it. Consolidating these layers is planned, one area at a time with testing, never a big-bang rewrite.

**API (`api/`, each file is a Vercel function; `_`-prefixed files are helpers, not routes):**
- `chat.js` — the brain. Big system prompt (character + "Bluey Intelligence" rules), OpenAI Responses API with a strict JSON schema returning `{reply, behavior, spellingSuggestion, brain}`. `brain` holds `mode` (DO/DISCOVER/GROW), goal/goalThread, `contextShifted`, readiness, promptQuality, `initiativeLevel` 0–4, opportunity rung/idea distance, environment, etc. The brain record is developer telemetry and must never be shown to users. Up to 5 images (data URLs, png/jpeg/webp/gif). Model from `BLUEY_MODEL`.
- `transcribe.js` (speech-to-text, 15 MB), `speech.js` (TTS, ≤4,096 chars; voice `echo` with "a warm, gentle Irish accent" in the instructions, chosen 2026-10-07; `BLUEY_SPEECH_VOICE` overrides; the browser fallback in `alpha36.js` and `index.html` `speak()` picks Connor (Irish), then Daniel/Arthur/Oliver/Ryan/George/Thomas/"UK English Male", then en-IE, en-GB, then a male en-US voice), `document.js` (PDF/Word/Excel via pdfkit/docx/xlsx).
- `_limit.js` — best-effort in-memory per-IP hourly limit + daily cap, applied to all four endpoints (chat, transcribe, speech, document). Resets per instance; the real backstop is the OpenAI account's monthly spend limit.

**Steer buttons** — `steer.js` + `steer.css` (loaded after `alpha40.js`). `chat.js` returns `brain.isDraft`; `steer.js` wraps `window.fetch` to read each `/api/chat` response (parsed before the caller gets it) and wraps `add()` to show Shorter / Warmer / More specific / Different angle under the latest draft only; a tap calls `send("Make it shorter.")` etc. Server side, `chat.js` detects a revision turn (latest user message starts with "make it/this/that", "shorter", "warmer", "try a different angle"…, right after an assistant message) and swaps the random reply-style nudge for an "edit your previous draft, keep every detail" nudge — the random nudges ("choose a fresh answer shape") made revisions start over and drop facts. Replies are capped at 4,000 output tokens; a cut-off reply returns a friendly 502. `steer.js` also adds a **More ▾** dropdown (formal, casual, simpler, bullets, plus two that prefill the composer) and, when `brain.assumption` is set, a "💭 … If that’s not right, just tell me." line (the old **Fix that** button was removed: unclear on its own). The revise-turn regex also matches "use simpler", "turn it into", "change it", "actually".

**Preferences** — `preferences.js` + `.css`. `brain.preferenceNoticed` → "Remember this for next time?" card; saved list (max 8, localStorage `bluey-preferences`) is added to every `/api/chat` body as `preferences`; `chat.js` sanitizes (strings, ≤120 chars, ≤8) and appends them to the instructions as style preferences only. **Remembered ▾** in the session tools lists/forgets them (full-width card on phones). Bluey must never claim cross-device memory.

**Greetings** — `greetings.js` redefines `blueyFirstMeet` / `blueyReturningMeet` (index.html calls them 420 ms after load): ~30 returning lines, weekday lines, July 4th Digital Day lines, no repeat of the last 8 (localStorage `bluey-greeting-recent`). Time-of-day lines stay in the status line (`blueyTimeRitual`). The original first-meeting intro never showed (it searched for the default greeting text after it had changed); `greetings.js` sets it directly.

**Marbles** — `marbles.js` + `.css` (after `rest.js`): when a new `.msg.assistant` in `#messages` or the `.stage-copy .greeting` text mentions marble or marbles as a whole word, 3–4 `.bluey-marble-drop` divs (first is always `m-storm`) are added to `.stage` level with the orb's bottom, just outside it, fall in with a bounce, rest 1.2–2.1 s, and roll off the nearer side with rotation (Web Animations), then are removed. Never while a batch is still rolling; reduced motion = fade only. The class is not `.bluey-marble`: index.html's Alpha 2 rare scene (`blueyMarbleScene`, a single marble on a timer) owns that name with `position:fixed` and a `left` keyframe. `window.blueyMarbles.drop()` for tests.

**Seasonal skies** — `seasons.js` + `.css` (after `marbles.js`) upgrade index.html's rare scenes, which index.html still schedules (`seasonalRareScene` every 75 s at 38%, `expandedSeasonalScene` every 90 s at 32%, both gated by `blueySceneAllowed`: 3 min apart, not while hidden or after "give me space"). It reassigns the global function names those timers call: `christmasSnowScene` → winter snow, `julyFourthScene` → fireworks (colored balls rise from orb level and burst, `.bluey-rocket` / `.bluey-flash` / `.bluey-ember`), `newYearScene` → gold/silver fireworks, `seasonalRareScene` → leaves Sep–Nov, Halloween, Christmas window (7 days before the 25th) 75% sleigh-or-snow, Dec–Feb snow 50%, July 4th window fireworks. Sleigh: 9 `.bluey-sleigh-ball` (index 0 is the red `.bluey-sleigh-lead`), flies through clear sky above the orb (above the `.stage-copy` if it's over his head and there's room, else between it and his head, else just over his head; with the first-visit talk hint on desktop there's no clear sky and it passes behind the status line). The old `birthdayScene` checked July 7 and index.html captured it in a `setTimeout` at load, so `seasons.js` runs its own `digitalDayScene` (July 4th only: "BLUEY'S DIGITAL DAY!" + 10 fireworks) at 3.8 s. Everything lives in `#bluey-scene-layer`, is positioned inside the `.stage` rect, moves with Web Animations, and removes itself; reduced motion = status line only. Preview: `?season=winter|snow|christmas|sleigh|july4|fireworks|birthday|newyear|fall` plays it at 2 s and every 25 s; `window.blueySeasons.play(name)`.

**Greeting placement** — `follow-copy.css` + `follow-copy.js` (all screen sizes) make `.stage-copy` (greeting + status) a fit-to-text column that follows the orb's live position (every frame while a finite animation or transition runs on the stage, other than the greeting's own glide; 15 times a second while only the endless idle bob runs; writes only when the rounded position changes), as Bluey drifts left/right and forward/back (the orb's size changes); it flips above him if there's no room below and stays on screen near edges. Selectors start with `body .app .stage` to beat the older phone stack in an `index.html` `@media(max-width:700px)` block (which used `!important` top/left/right) and `alpha47-mobile-polish.css` (injected late by `alpha46.js`).

**Light bulb / tap-to-answer card** — `tips.js` + `tips.css`. `chat.js` returns `brain.betterPrompt`, `brain.betterPromptWhy`, and `brain.tipSlots` (one `{blank,label,options[≤3]}` per `[blank]`; empty options = text box for personal details). Server: drops a 💡 with >2 blanks, strips an unstated "first-time", normalizes slot brackets, dedupes, and adds a slot for any blank the model forgot. `tips.js` builds a card: the sentence (added words `<mark>`ed, blanks as `.bluey-fill` that fill live), chips + "Other…" per slot, and **Write it** (disabled until every blank is filled; sends the filled sentence). If the brain is asking (`!isDraft` and `needsQuestion`/`DISCOVER`) the card opens inline under Bluey's reply with no 💡; otherwise a 💡 under the user's message opens it. After the card is answered, `chat.js` detects that the user is replying to Bluey's own short question (previous assistant message <400 chars with `?`/"tell me"/"let me know") and swaps the reply-style nudge for "deliver the full result now, don't ask again, state assumptions" (live bug: 2 of 3 filled cards got a second question). Brain Lab case `answered-delivers`. The scorer counts "tell me / let me know / share / paste / send me / upload" as asking (no `?` needed). Hides `#bluey-prompt-start`. **The real test is `scripts/tip-eval.mjs`** (local only, `.vercelignore`d; reads `.env`): A/B per vague request with hidden background; blanks answered the way a person uses the card (pick the fitting chip or type ≤10 words); blind judge scores, invented facts (with a quote), and `tipFocus` 1–5. Pass bar: ≥80% wins, ≥ +1.5 avg, 0 invented, focus ≥ 4, no 💡 on clear requests. Averages can hide one bad 💡, so add targeted Brain Lab cases for known failures (`tip-proposal`, `tip-asking`). Restart `vercel dev` between runs (the per-IP limiter counts test calls). Brain Lab also checks every blank has exactly one slot, ≤3 distinct chips, short labels.

**Hand-off kit** — `chat.js` returns top-level `handoff` (`title, platform ∈ Claude|ChatGPT|Gemini|NotebookLM, feature (enum, server keeps it only if it belongs to that platform), why, alsoPlatform, alsoFeature, alsoWhy, prompt`) for jobs Bluey can't do here (build/run apps, images/video, schedules, accounts, long research, document workspaces). Rules under "HAND-OFF KIT"; a per-turn `handoffIntent` nudge (build/create … app/website/dashboard/tool/logo/video, or every Monday/daily/remind me) forces the hand-off and forbids implying Bluey will do it (live bug before: "what time should I send it?"). `handoff.js` + `.css`: card with Copy prompt, Open (copies; `?q=` prefill for ChatGPT/Claude under 1,800 chars; Claude Code → claude.ai/code, Codex → chatgpt.com/codex), Download PDF via `api/document.js` **direct content mode** (`content:{title,paragraphs,bullets}` → no model call, exact text). Test: `scripts/handoff-eval.mjs` (original vs filled super prompt through a stand-in OpenAI assistant, blind judge, platform fit 1–5; can't run Claude Code/Gemini itself, so it measures the prompt). Brain Lab: `handoff-build`, `handoff-schedule`, `handoff-image`, `handoff-none`; runner passes `_handoff`. **Official help sites** (`OFFICIAL_DOCS` in `chat.js`; listed in the prompt under "OFFICIAL HELP SITES"): on a `handoffIntent` turn the `web_search` tool gets `filters.allowed_domains: OFFICIAL_DOCS`, and `handoff.steps` (3–7 beginner steps from those pages) plus `sources` (official pages, or citations as a fallback) show in the card as "How to set it up" and "Official help" (help-center home if no search). Super prompts must ask for the finished result (not a plan), list assumptions, and self-check that the 1–3 key details are present as values or [blanks]. Studying several of your own documents → NotebookLM hand-off. `sources.js` skips its list when a hand-off card is shown. Eval history (4 runs, pass on run 4: 8/8, +3.0, fit 4.5) is in the README.

**Creator recognition** — `creator.js` (loaded right after `format.js`): `/?creator=<code>` saves the code in localStorage `bluey-creator` (8–80 chars of A–Z a–z 0–9 _ -), removes it from the URL with `window.history.replaceState` (the app's global `history` is the chat array and hides the browser's), shows "Hi K.Y.!" after the first-visit status, and adds `creator` to every `/api/chat` body; `?creator=off` forgets it. Because a Home Screen app on iPhone has its own storage and no address bar, typing `creator: <code>` (or `creator: off`) in the message box does the same: a capture-phase `submit` listener on `#form` catches it, saves it, clears the box, and stops the event, so it never reaches the chat or `/api/chat`. `blueyIsCreator()` lets `greetings.js` use `CREATOR_LINES` (cosmetic only). `chat.js` compares it with env `BLUEY_CREATOR_CODE` (Vercel production secret, sensitive; never commit or print it) using `timingSafeEqual`; on a match `creatorNote` ("THE CREATOR IS HERE…") is appended at the very end of the instructions (mid-prompt it was sometimes ignored). Prompt section "WHO IS TYPING": without that note, never confirm a creator/parent/K.Y. claim, be warm, don't hint at how the check works.

**Memory on this device** — `chat.js` returns top-level `remember` (≤3 `{kind: about_me|project|goal|other, subject ≤60, fact ≤240}`) and `forget` (≤5 subjects, or "everything"); prompt section "MEMORY (on this device)" (use naturally, never claim anything not in the list, remember only lasting facts the person shared about themselves, one-time task details are not facts, never sensitive data, nothing from practice talks or scam checks, preferences stay in `preferenceNoticed`). The server drops sensitive-looking memories (`sensitiveMemory` regex: SSN/passport/license/password/PIN/card/account/routing numbers/diagnosis/medication, 9- and 12–19-digit numbers) and returns none during practice talks or scam checks. The request carries `memory` (≤30); `memoryNote` lists it in the instructions as "WHAT YOU REMEMBER ABOUT THIS PERSON". `memory.js` + `.css` (after `practice.js`): localStorage `bluey-memory` (max 30, one per subject, case-insensitive), "💾 I'll remember: …" / "🧹 Forgotten: …" notes with Undo under the reply, **What Bluey remembers** in the + menu (count) opening a sheet grouped About you / Projects / Goals / Other / How you like answers (the `bluey-preferences` list), Forget per row, two-tap Forget everything; facts are stored about the person ("Their name is Jason.") and shown as "Your name is Jason." (`toYou`). The old Remembered dropdown (`.bluey-plus-remembered`) is hidden. `window.blueyMemory.{list, remember, forget, refresh}`. Same shape as the `memories` table in `supabase/accounts_v1.sql`.

**Wikipedia pictures** — `chat.js` returns top-level `pictures` (`null` or `{query, source:"Wikipedia", items:[{thumb, title, page, file, credit, license}]}`). The brain sets `pictures.query` (schema `{query}`; prompt section "PICTURES": Wikipedia-style subject; never private people, sexual/violent/medical, products, news, scam checks, practice; never describe a specific photo; no web search needed). `api/_pictures.js` `wikiPictures(query)`: search → first non-disambiguation article with a page image → that article's REST `media-list` in page order → keep the lead image plus files whose names contain a subject word (≥4 letters, minus stop words), skipping SVG/GIF/maps/logos/flags/caricatures/portraits → Commons `imageinfo` (480px thumb, Artist, LicenseShortName, Categories) → drop unsafe categories. When every word of the article title is in the query plus more ("Pan Am Boeing 747" → "Boeing 747"), only files whose compacted name contains the extra words ("panam") are kept; fewer than 2 → Commons file search (`list=search`, namespace 6, `filetype:bitmap`) with the same filter; short titles with no 4-letter word match the compacted title; the lead image only has to pass `NOT_A_LEAD` (no logos/maps; "Wikimedia" in the name is fine); `imageinfo` comes from the Commons API, so Wikipedia-local non-free files (most logos) are left out. If `pictures.query` was set but nothing was found, `chat.js` adds "I couldn’t find good pictures of that on Wikipedia just now…" to the reply (live bug: "Sure, Ky!" with no pictures); the same line is added when the reply claims pictures ("Here are a few pictures…", `claimsPictures`) but none came back, and the PICTURES rules say a reply that promises pictures must set `pictures.query` (also after a correction like "actually I meant the motorcycle"). Brain Lab case `pictures-correction`; thumbnails come from `thumb.wikimedia.org` or `upload.wikimedia.org` (utm query stripped); 4 s deadline, never throws. Fetched in parallel with source previews; skipped for drafts, scam checks, practice talks. `pictures.js` + `.css` (after `sources.js`, before `offers.js`): "Pictures of X, from Wikipedia" grid (2 columns on phones, 4 on desktop), credit · license under each, tap opens the Commons file page; only wikipedia/wikimedia URLs are rendered.

**Source pictures** — `api/_previews.js` `addPreviews(sources)`: after a search, reads each source page's `og:image` / `twitter:image` (or `link rel=image_src`) and adds `image` to that source. Only public http(s) hosts (`isPublicHost` blocks localhost, private and link-local ranges; redirects followed manually, max 3, each host checked), ≤300 KB per page (stops at `</head>`), 3 s overall deadline, https images only. `chat.js` skips it for scam checks and practice talks. `sources.js` shows a 72×50 thumbnail per source (`.bluey-sources-thumb`, `referrerPolicy=no-referrer`, removed on load error). Many sites have no preview or block bots (403); that's expected.

**Web search** — `chat.js` offers OpenAI's `web_search` tool (with `include: ["web_search_call.action.sources"]`) only while `searchAllowed(req)` (`_limit.js`: 15 searches per visitor per day, 300 per day overall, counted with `noteSearch` only when the model actually searched); otherwise the instructions say search is unavailable. Brain Lab cases `search-jobs`, `no-search-writing`; the runner passes `_searched`/`_sources` into `checkExpectation`.
